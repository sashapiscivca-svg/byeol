# Посібник з інтеграції

[English](INTEGRATION.md) · **Українська**

Цей посібник пояснює, що потрібно, щоб під'єднати byeol до реального дрона або до записаних логів: входи, системи координат, одиниці, контракт виходу й режими відмов. Метод і його перевірку описано в [TECHNICAL_REPORT.uk.md](TECHNICAL_REPORT.uk.md).

> byeol лише **читає** дані датчиків. Ніколи не подавайте його вихід назад у керування польотом чи логіку безпеки.

## 1. Встановлення

```bash
pip install -e .              # лише numpy
pip install -e ".[yaml]"      # + YAML-профілі камер
pip install -e ".[eval]"      # + OpenCV/SciPy для оцінки, калібрування та бази фазової кореляції
```

Python ≥ 3.10. Ядро імпортує лише numpy, тому працює на Raspberry Pi із системним numpy.

## 2. Входи

Усі входи мають **один годинник** у секундах, зазвичай час від запуску польотного контролера (ПК). Якщо камера використовує інший годинник, зіставте його через `byeol.timebase.ClockMap` або задайте `EgoConfig.cam_imu_offset`, визначений як `t_imu = t_camera + offset`.

| Виклик | Одиниці / система | Частота | Обов'язковий | Примітки |
|---|---|---|---|---|
| `push_imu(t, gyro, accel)` | рад/с і м/с² (питома сила), тіло **FRD** | 100–400 Гц | так | Відліки з NaN/Inf, `\|ω\| > 35 rad/s` або часом, що не зростає, відкидаються (`est.stats["dropped"]`). |
| `push_velocity(t, v_ned, sigma)` | м/с, світ **NED**; σ у м/с | 5–10 Гц (≥1 Гц) | **так** | Швидкість з EKF ПК, напр. MAVLink `LOCAL_POSITION_NED`. Якщо вона старша за `vel_max_age` (1 с), результат — `stale_velocity`. |
| `push_height(t, h, source)` | м над **поверхнею, яку знімаємо** | 5–10 Гц | так | `source` ∈ `HeightSource`. Відліки з джерел, відмінних від основного й резервного, ігноруються й підраховуються. |
| `push_gimbal(t, theta)` | рад; 0 = вперед горизонтально, π/2 = надир | на кожен кадр або при зміні | так | Нерухомій камері теж потрібен один виклик із кутом її кріплення. |
| `push_heading(t, yaw)` | рад, NED (за годинниковою стрілкою від півночі) | 2–5 Гц | рекомендовано | Узгоджує курс світу фільтра із системою NED швидкості ПК. |

### Джерело висоти (`HeightSource`)

| Значення | Застосування | Типова абсолютна σ (припущення) |
|---|---|---|
| `FUSED_FC` | Злита висота ПК. Основне джерело над водою, де далекоміри дають хибні відбиття. | 0,4 м |
| `RANGEFINDER` | Лідар або сонар над сушею, якщо є | 0,1 м |
| `BARO` | Барометр. Його треба привести до рівня поверхні, бо він вимірює висоту над точкою зльоту. | 1,0 м |
| `MANUAL` | Стала висота, введена оператором | 2,0 м |

Входи висоти налаштовуються такими полями `EgoConfig`:

- `height_source`: основне джерело.
- `height_fallback`: резервне, напр. основне `RANGEFINDER` з резервним `FUSED_FC`.
- `height_trust` ∈ (0, 1]: використовується σ = `σ_abs / trust`.
- `height_max_age`: наскільки старим може бути відлік висоти.

Типові значення σ **не виміряні**. Відкалібруйте їх для свого обладнання.

### Конвертери зовнішніх форматів

Оцінювач приймає лише SI, NED/FRD і один годинник. Перетворюйте на межі, у коді, який читає зовнішній формат:

- `byeol.units`: `feet_to_m`, `knots_to_ms`, `kmh_to_ms`, `mph_to_ms`, `fpm_to_ms`, `cms_to_ms` (MAVLink, см/с), `cdeg_to_rad` (MAVLink, сотні градуса), `mm_to_m` і `to_si(x, unit)`.
- `byeol.frames`: `ned_to_enu` / `enu_to_ned`, `frd_to_flu` / `flu_to_frd`, `yaw_ned_to_enu` / `yaw_enu_to_ned`, а також матриці повороту між конвенціями NED/FRD і ENU/FLU (ROS REP-103).
- `byeol.timebase`: UTC/Unix ↔ секунди GPS з урахуванням високосних секунд, тиждень GPS + TOW, а також `ClockMap.fit(t_this, t_other)` для лінійного зіставлення годинників, оціненого за парними подіями.

## 3. Камера

```python
from byeol.cameramodel import CameraModel, Distortion
cam = CameraModel.from_pixels(1280, 720, fx=915.0, fy=915.0, cx=639.5, cy=359.5,
                              dist=Distortion(k1=-0.12))
cam = CameraModel.from_mm(640, 512, focal_mm=13.0, sensor_w_mm=7.68, sensor_h_mm=6.14, kind="lwir")
cam = CameraModel.from_fov(640, 360, hfov_deg=70)

from byeol.camprofile import load_camera, dump_camera
cam = load_camera("configs/cameras/generic_lwir_320x256_hfov45.yaml")   # .json не потребує додаткових залежностей
```

- **Піксельні координати задаються в тому кадрі, для якого визначено модель.** Якщо ваш трекер працює на зменшеному кадрі, передайте `cam.resized(w, h)` або `cam.binned(b)` / `cam.cropped(x0, y0, w, h)`. Фокусна відстань у пікселях масштабується, а поле зору зберігається.
- Калібруйте шахівницею: `python scripts/calibrate_camera.py --help` (потрібен OpenCV). Скрипт записує профіль YAML/JSON. Для тепловізійних камер використовуйте дошку, контрастну в довгохвильовому інфрачервоному діапазоні.
- Якщо ваші кадри вже виправлено від дисторсії, задайте нульову дисторсію.
- Профілі в `configs/cameras/` — **ілюстративні шаблони**, а не дані виробників.

## 4. Контракт виходу

```python
r = est.frame_shift(t0, t1)    # t0 < t1, обидва — моменти кадрів камери
```

| Поле | Значення |
|---|---|
| `dx`, `dy` | Піксельне зміщення вмісту зображення від кадру t0 до кадру t1 (+dx праворуч, +dy вниз) в опорному пікселі. Типово це центр кадру. З `EgoConfig.pixels=(N,2)` — середнє за заданими пікселями. |
| `cov` | Коваріація 2×2, пікс² |
| `sigma` | `sqrt(trace(cov)/2)`, пікс |
| `conf` | `1 / (1 + λmax(cov))` ∈ (0, 1]. **Не порівнюється** з `resp` фазової кореляції. |
| `valid` | `False` → `dx = dy = NaN`, `cov = 1e6·I`, `conf = 0` |
| `reason` | `ok` або код відмови (нижче) |
| `height_source` | яке джерело висоти використано |
| `as_tuple()` | `(dx, dy, conf)`, та сама форма, що й у `dal.ego.estimate_shift` |

Щоб передбачити, куди зміститься точка: `u₁ ≈ u₀ + (dx, dy)` поблизу опорного пікселя. Для точок далеко від центру при нахиленій камері передайте точки інтересу в `pixels`.

### Коди відмов

| `reason` | Причина | Типове виправлення |
|---|---|---|
| `no_imu` | Менше 3 відліків IMU, t0 раніше за початок історії, t1 більш ніж на 50 мс пізніше за останній відлік IMU, або t1 ≤ t0 | Перевірте потік IMU й синхронізацію годинників |
| `no_height` | Немає відліку від основного чи резервного джерела в межах `height_max_age` | Перевірте налаштування `HeightSource` |
| `low_height` | h < 1 м | Очікувано на землі або під час зльоту |
| `no_gimbal` | `push_gimbal` жодного разу не викликали | Викличте хоча б раз, навіть для нерухомого кріплення |
| `no_velocity` / `stale_velocity` | Швидкості ПК немає, або вона старша за 1 с | Передавайте швидкість ПК із частотою 5–10 Гц |
| `horizon` | Промінь опорного пікселя не перетинає площину поверхні (камера дивиться вище горизонту) | Нахиліть підвіс донизу або використайте інші опорні пікселі |

Допоміжна функція злиття додає ще три коди: `fused`, `vision_only` і `vision_gate`.

## 5. Злиття з оцінкою із зображення (опційно)

```python
from byeol.fuse import fuse
r2 = fuse(r, (dx_v, dy_v, resp))   # результат фазової кореляції в тому самому масштабі пікселів
```

Злиття з вагами, оберненими до дисперсій, з `σ_v = max(0.3/resp, 0.2)` пікс. Візуальна оцінка з `resp < 0.1` ігнорується. Якщо дві оцінки неузгоджені на рівні 99 %, лишається та, що має меншу σ. Якщо фізична оцінка невалідна, використовується лише візуальна. Коефіцієнти підібрано на синтетичній воді, тому **перекалібруйте їх на своїх записах**.

## 6. Рекомендована поведінка споживача

1. Використовуйте `valid` і `conf` і ніколи не ігноруйте `cov`. У синтетичних наскрізних тестах трекер, який приймав малодостовірну оцінку руху камери як точну, з часом втрачав ціль. Цього уникають брамка за впевненістю близько 0,1 і передавання σ у фільтр Калмана трекера ([TECHNICAL_REPORT.uk.md](TECHNICAL_REPORT.uk.md) §5.6).
2. Сприймайте `valid=False` як «інформації немає». Переходьте на власну оцінку із зображення, лише якщо вона має власну надійну брамку за впевненістю; інакше вважайте, що руху немає.
3. За високої частоти кадрів (≥30 к/с) компенсація руху камери може бути зайвою. Виміряйте, перш ніж на неї покладатися.

## 7. Параметри налаштування (`EgoConfig`)

| Група | Параметри (типові значення) |
|---|---|
| Шум | `gyro_density` 3e-4 рад/с/√Гц, `bias_sigma` 0,003, `bias_sigma0` 0,015 рад/с, `bias_tau` 12 с, `scale_sigma` 0,005, `time_sigma` 0,003 с, `gap_rate_sigma` 0,3 рад/с, `tilt_sigma` 0,03 рад, `height_rel_sigma` 0,03, `vel_model_sigma` 0,05 м/с, `floor_px` 0,05 |
| Стійкість | `max_gap` 0,03 с, `max_extrap` 0,05 с, `max_rate` 35 рад/с, `history_s` 3 с, `min_height` 1 м, `height_tau` 1 с, `vel_max_age` 1 с, `height_max_age` 2 с |
| Фільтри | `mahony={kp, ki, kp_yaw, ki_yaw, gate, accel_tau}`, `kf={accel_noise, bias_walk, p_v0, p_b0}`, що передається у `VelocityKF` |
| Лише для досліджень | `require_velocity=False`, `zero_vel_sigma` |

Оцініть `gyro_density` і шум акселерометра за статичним записом або візьміть їх із даташиту IMU. Виміряйте `cam_imu_offset` за допомогою калібрувального маневру з обертанням, як описано в [RECORDING_PROTOCOL.uk.md](RECORDING_PROTOCOL.uk.md).

## 8. Відтворення логів

`scripts/eval_dataset.py` — еталонний цикл. Він об'єднує всі потоки за часовими мітками й подає їх по порядку. За однакового часу висота подається раніше за швидкість, а підвіс — безпосередньо перед кожним запитом кадру. Той самий цикл працює для реальних логів, записаних у форматі з [RECORDING_PROTOCOL.uk.md](RECORDING_PROTOCOL.uk.md).
