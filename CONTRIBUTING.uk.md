# Як долучитися до byeol

[English](CONTRIBUTING.md) · **Українська**

Дякуємо за допомогу. byeol існує, щоб допомагати знаходити людей у небезпеці, і важливий кожен внесок, хоч великий, хоч малий. Роблячи внесок, ви погоджуєтеся, що він поширюється за [ліцензією MIT](LICENSE), і підтверджуєте, що прочитали [ETHICS.uk.md](ETHICS.uk.md).

## Що допомагає найбільше

1. **Записи реальних польотів.** Їх проєкту бракує найбільше. Потрібні синхронізовані IMU, стан польотного контролера, висота, кут підвісу й відео, записані під вільною ліцензією (CC BY 4.0 або CC0), найкраще над водою. Дотримуйтеся [docs/RECORDING_PROTOCOL.uk.md](docs/RECORDING_PROTOCOL.uk.md) і відкрийте issue, щоб обговорити, як передати дані.
2. **Вимірювання на цільовому залізі.** Запустіть `python scripts/bench_budget.py` на Raspberry Pi Zero 2 W чи подібній платі й надішліть результат разом із назвою плати, ОС і версією numpy.
3. **Відкалібровані профілі камер.** Профілі з реального калібрування (`scripts/calibrate_camera.py`) із моделлю камери, роздільністю, датою й RMS калібрування. Не переписуйте характеристики виробника без первинного джерела.
4. **Читачі логів** PX4 ULog, ArduPilot DataFlash чи MAVLink tlog, що перетворюють їх у формат потоків, який використовує `scripts/eval_dataset.py`.
5. **Повідомлення про помилки** з мінімальним відтворенням (входи, `EgoConfig`, очікуваний і фактичний `EgoResult`).

## Порядок розробки

```bash
pip install -e ".[dev]"
python -m pytest tests -q          # усі тести мають проходити
ruff check .                       # лінтер без помилок
python scripts/make_dataset.py --check   # якщо змінювали synth.py, див. нижче
```

- Ядро (`src/byeol`) має залежати **лише від numpy**. Опційні залежності імпортуйте ліниво, з зрозумілим повідомленням про помилку.
- Кожен новий модуль і скрипт додайте до [docs/MODULES.md](docs/MODULES.md); це перевіряє тест.
- Усередині оцінювача — одиниці SI, системи NED/FRD і один годинник. Перетворення робіть на межі (`units.py`, `frames.py`, `timebase.py`).
- Додавайте тести на нову поведінку. Для геометрії краще аналітичні перевірки на випадках із точним розв'язком.
- **Не змінюйте опубліковані числа мовчки.** Якщо зміна впливає на результати, перезапустіть відповідний скрипт із [docs/TECHNICAL_REPORT.uk.md](docs/TECHNICAL_REPORT.uk.md), §8, оновіть `experiments/` і документацію обома мовами, поясніть зміну в pull request і в [CHANGELOG.md](CHANGELOG.md).
- Якщо змінюєте `synth.py`, датасет перестає відтворюватися як v1. Підніміть версію датасету замість перезапису `byeol-synth-v1`.
- Суттєві проєктні зміни оформлюйте новим записом у [docs/DESIGN_DECISIONS.uk.md](docs/DESIGN_DECISIONS.uk.md) з причиною й альтернативами.

## Документація

Уся документація для користувачів двомовна: англійська (`*.md`) і українська (`*.uk.md`). Оновлюйте обидві версії в одному pull request або вкажіть у ньому, що переклад ще потрібен. Пишіть кожен абзац і пункт списку одним рядком, без ручних переносів.

## Pull request

- Одна тема на pull request, з чітким описом, що змінено й чому.
- Звітуйте чесно: наводьте й негативні результати, і умови, за яких ваша зміна не допомагає.
- Поважайте інших. Див. [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
